deterministically. That verifies repeatability, source identity, section
boundaries, and generated bytes. It does **not** yet verify rendered table
geometry, meaningful typography, or bridge semantics.

## Review Checklist

### `«Косая система»`

- [ ] Wording agrees with the rendered RTF.
- [ ] Table geometry and multiline cells are represented correctly.
- [ ] The section should remain one note, or its child headings should become
  separate semantic notes.
- [ ] The two source hyperlinks described as `по этой ссылке` resolve to the
  intended future notes.

### `Ответы на 1♣`

- [ ] Wording agrees with the rendered RTF.
- [ ] Dense tables, multiline auctions, and merged cells are represented
  correctly.
- [ ] Child headings identify sensible semantic note boundaries.
- [ ] Internal source hyperlinks resolve to the intended future notes.

### `Шлемовая торговля`

- [ ] Wording agrees with the rendered RTF.
- [ ] Lists and mixed Russian/English passages retain their intended grouping.
- [ ] Tables and auction layouts are represented correctly.
- [ ] Child headings identify sensible semantic note boundaries.
- [ ] Internal source hyperlinks resolve to the intended future notes.

## Findings to Resolve Before Promotion

- The RTF outline hierarchy is usable, but it skips numerical levels. The
  pilots compress those gaps into ordinary Markdown heading levels.
- Adobe Symbol suits, arrows, and notation are converted to visible Unicode;
  the private-use horizontal arrow extender is represented as `─`.
- `TOC` backlink text is retained as an HTML source-navigation comment rather
  than partnership content.
- Table text is preserved, but cell geometry is intentionally not guessed.
- Font weight, italics, color, indentation, and merged cells are not yet
  represented.
- Human confirmation is still required before any pilot moves into
  `system/agreements/` or is split into authoritative semantic notes.
